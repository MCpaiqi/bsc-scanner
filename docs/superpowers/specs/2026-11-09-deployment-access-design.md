# Deployment access boundary

Intent: close RESEARCH_RELIABILITY.md R13 for the single-owner BSC/PAPER research desk, preserving R3/R11/R14 and existing data. User delegated continued optimization and verified pushes; continue autonomously, no deployment/production data operation.

Approaches considered (executor choices): network-only protection leaves browser/local API clients able to alter research; full identity-provider/RBAC introduces user-management infrastructure absent from this single-owner app. Choose private default Compose ports plus one explicit analyst Bearer secret for the existing six annotation/rule mutation routes. Read-only market/research GETs and the non-persisting wallet replay remain available; read access is intended for a private workstation/network, not confidential multi-tenant isolation.

Contract:
- No SMMS_ANALYST_KEY => analyst writes503/ANALYST_READ_ONLY. Configured key => missing/wrong/malformed/duplicate Authorization401/ANALYST_UNAUTHORIZED; constant-time byte comparison, header-only, no cookies/query keys or bypass flag. Authorization runs before opening a DB session. Existing annotation revisions, idempotent rules and outbox commits remain intact.
- GET /api/radar/access returns enabled/authorized booleans only and Cache-Control:no-store. Secret is SecretStr,32..256URL-safe ASCII characters; invalid setting errors/repr/model dumps must not disclose values. Blank is disabled. Existing read-only wallet replay is not a persistent analyst write.
- React AnalystWorkflow offers a labelled password input (paste/password-manager compatible), unlock/lock, explicit disabled/loading/error states. Key lives only in current JS page memory; refresh/lock forgets it. Only access validation and mutation requests receive Authorization; no storage, URL, SSE or ordinary GET propagation. Unauthorized response clears local authorization, preserves note draft, and asks for re-authorization; no automatic write retry. Reject credential transmission to non-loopback HTTP origins; remote use requires HTTPS.
- Compose API8000/Web8080 bind127.0.0.1. PostgreSQL/Redis have no published ports. PostgreSQL password is required, never a baked default. Structured DATABASE_HOST/PORT/USER/NAME/PASSWORD (SMMS_POSTGRES_PASSWORD alias) builds the existing database_url using SQLAlchemy URL escaping; raw URL remains supported outside structured mode and is excluded from Settings repr/dumps. Compose DB host overrides local.env host for containers. Redis stays internal; no new auth identity service or dependency.
- New stdlib scripts/init_local_env.py creates a fresh.env from.env.example with distinct random secrets, exclusive0600creation and no credential stdout; refuses existing files/symlinks. Never modify this workspace's existing.env/.venv/uv.lock or old releases/data. Existing PostgreSQL volumes require explicit password rotation using the old administrator; never reset/delete volumes. Docs distinguish setup from rotation and reflect actual services.
- CI corrects the prior unused provider aliases; real Python authorization/transaction tests, frontend interactions, Compose rendered-config checks and authenticated runtime/web smoke run without live providers or production writes. Full Compose persistence/restart remains R14.

Builder decisions: no new packages; reuse FastAPI/Pydantic/SQLAlchemy and existing visual tokens. This is single shared analyst authorization, not per-user auditing or shared-secret revocation on browser lock. Requests already accepted by the server may finish after local lock. Risks if wrong: config/generator faults require setup correction; leaked shared key requires server-side rotation; multi-user deployment would need separate identity work.
