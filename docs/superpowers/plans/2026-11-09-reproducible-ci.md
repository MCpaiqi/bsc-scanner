**Evidence:** No tracked .github workflow or Python lock. scripts/test.py installs editable dependencies afresh; Docker does an unconstrained pip install. **Architecture/choice:** Keep declared Python compatibility ranges and existing tested package versions as the initial baseline, compile universal hash-pinned requirements/runtime.lock and dev.lock (both include explicit build tools), and install with pip --require-hashes --only-binary. Install first-party code without dependency resolution/build isolation after the locked build tools. A stdlib script checks dependency-input fingerprints and lock hashes, and invokes pinned uv only for explicit lock generation; it never creates/syncs a project environment or root uv.lock. Exact npm direct versions preserve the existing locked graph, with npm ci. Alternative root uv.lock adoption would overwrite an existing untracked file and couple setup to a project manager; unpinned install cannot prove reproducibility. Existing autonomous authorization opts out of another approval round.

**Runtime/toolchain:** CI validates Python3.12 and3.13 (production minimum and local tested runtime), including Windows3.13; Node24.15.0/npm11.12.1 matches jsdom30.0.1 engine requirements verified during clean installation. Actions are pinned to verified official commit SHAs; contents permission read-only, checkout credentials not persisted. Container base images are pinned by registry digest after inspection. Runtime and web images are built/tested in CI without publishing. OS/ABI variants remain explicit; this is dependency/source reproducibility, not a promise of bit-identical OS images across platforms.

Workflow PR jobs must not expose repository credentials or deploy/publish. Real Redis/PostgreSQL tests must run, not all skip; provider-network tests remain explicitly disabled. The current lock graph is preserved unless compatibility evidence requires a change.

Run in the verified existing codex/research-integrity feature workspace. Windows POSIX skill helpers are replaced by this plan and its own ignored scratch/evidence directory. Generate/install only in new owned temporary directories; never clean or repurpose existing .venv, uv.lock, release files or data. A uv pip compile resolver invocation is not a uv project sync/run and does not mutate those files; the previous rejected recursive cleanup remains prohibited. GitHub connector lacks push-workflow listing and gh is absent; use the best authenticated read-only fallback if required, with credentials kept only in memory and never printed. Prefer connector job/log tools once run IDs are known.

Primary reference checked for universal/hash compilation: https://docs.astral.sh/uv/pip/compile/ . Official Actions tags were resolved directly from their public repositories before pinning. Local Docker daemon failure is environment evidence, not proof an image builds; actual CI image verification remains required.
